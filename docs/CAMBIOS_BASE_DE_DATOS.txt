======================================
Fecha: 21-10-2026
Archivo de la base: database/aquaroma.sql (es el ÚNICO archivo SQL del proyecto)

Este documento explica solo los cambios hechos a la base de datos: qué se agregó,

1. Cómo instalar o actualizar la base
-------------------------------------
Se ejecuta aquaroma.sql completo:
  - MySQL Workbench: File > Open SQL Script... > database/aquaroma.sql > botón del
    rayo (Execute).
  - Terminal:  mysql -u root -p < database/aquaroma.sql

IMPORTANTE: el archivo empieza con DROP DATABASE IF EXISTS aquaroma. Borra la base
completa y la crea de nuevo con todas sus tablas, triggers, procedimientos, vistas y
datos de prueba.
  - Se pierde lo que se haya creado a mano (por ejemplo, cuentas registradas para
    probar).
  - Las cuentas de prueba se vuelven a crear solas:
      Administrador: admin@aquaroma.cl  / Admin.2026
      Cliente:       benjamin@email.cl  / Cliente.2026

Antes había 3 scripts sueltos para actualizar una base sin borrarla
(agregar_productos.sql, hu016_descripcion_larga.sql y hu008_ventas_prueba.sql). Se
eliminaron para no repetir el mismo SQL en dos lugares: todo su contenido está en
aquaroma.sql.

Prueba hecha: aquaroma.sql se ejecutó completo en una base temporal
(aquaroma_prueba, borrada después). Las 105 sentencias corrieron sin errores, y

3. Nueva columna: producto.descripcion_larga (HU-016)
-----------------------------------------------------
Dónde está: en el CREATE TABLE producto, justo debajo de "descripcion".

  descripcion_larga TEXT NULL

Para qué sirve: la HU-016 (ficha de detalle del producto) pide mostrar la
"descripción completa". La columna "descripcion" que ya existía tiene textos cortos
("Tropical y dulce") que el catálogo usa como etiqueta de color, así que se agregó
una columna aparte para el texto largo.
  - descripcion        -> etiqueta corta del catálogo (no cambió).
  - descripcion_larga  -> párrafo que se muestra en la ficha (/catalogo/<id>).

Puede quedar vacía (NULL). En ese caso la ficha muestra la descripción corta.

Cómo se llena (bloque "DESCRIPCIÓN COMPLETA PARA LA FICHA DEL PRODUCTO"):
  Un UPDATE con CASE escribe el texto de cada producto según su SKU:
    UPDATE producto SET descripcion_larga = CASE sku
        WHEN 'AQ-LIM-500' THEN 'Agua sin gas con el aroma cítrico del limón...'
        ...
    END
    WHERE sku IN ('AQ-LIM-500', ...);
  El WHERE limita el cambio a esos 11 productos. Además, MySQL Workbench (en modo
  seguro) no deja hacer un UPDATE sin un WHERE sobre una columna clave como sku.

Para cambiar un texto después:
  UPDATE producto SET descripcion_larga = 'Nuevo texto...' WHERE sku = 'AQ-MAN-500';


4. Productos nuevos del catálogo
--------------------------------
Bloque en aquaroma.sql: "PRODUCTOS DEL CATÁLOGO WEB (HU-013, HU-016) Y STOCK INICIAL".

Se agregaron 5 sabores. Ya existían sus imágenes en public/img, pero no se usaban:

  SKU         Producto                  Tipo          Etiqueta            Imagen                 Stock
  AQ-MAN-500  AQUAROMA Mango            Electrolitos  Tropical y dulce    agua_mango.png         18
  AQ-FRR-500  AQUAROMA Frutos rojos     Con gas       Intenso y frutal    agua_frutos_rojos.png  14
  AQ-HIB-500  AQUAROMA Hibisco y rosa   Sin gas       Floral y delicado   hibisco_y_rosa.jpg     10
  AQ-LYM-500  AQUAROMA Limón y menta    Con gas       Cítrico y herbal    limon_y_menta.jpg      16
  AQ-PYL-500  AQUAROMA Pepino y limón   Sin gas       Fresco y ligero     pepino_y_limon.jpg     12

Todos cuestan $1.490, son botella PET de 500 ml, se pueden personalizar y su stock
está en la sucursal 1 (Aquaroma Santiago).

Cómo se insertan (4 pasos):
  1. tipo_agua: Con gas, Sin gas y Electrolitos. Ya existían, no cambiaron.
  2. categoria: se agregaron 5 aromas nuevos (Mango, Frutos rojos, Hibisco y rosa,
     Limón y menta, Pepino y limón). En total hay 11.
  3. producto: cada producto se describe con NOMBRES ('Sin gas', 'Mango'...) dentro
     de una tabla temporal llamada "datos". Los JOIN buscan el id que corresponde a
     cada nombre. Así no hay que escribir números de id a mano y el script no falla
     si los id cambian.
  4. inventario: stock inicial de cada producto, buscado por su SKU. Frutilla y
     Arándano quedan en 0 para probar el estado "Agotado".

Dónde se ve: /catalogo (11 productos y 11 filtros de aroma) y la ficha de cada uno.

Pendiente: "Limón y menta" y "Pepino y limón" son un aroma propio. Por eso, al
filtrar por "Limón" no aparecen. Para que aparezcan habría que permitir varios
aromas por producto, lo que implica cambiar la estructura de la base.


5. Ventas de prueba para "Más vendido" (HU-008)
-----------------------------------------------
Bloque en aquaroma.sql: "VENTAS DE PRUEBA PARA "MÁS VENDIDO" DEL INICIO (HU-008)".

Para qué sirven: la página de inicio marca como "Más vendido" al producto activo
con más unidades vendidas. La única venta que había en la base era del producto
antiguo AQ-001, que está desactivado, así que la etiqueta nunca aparecía. Todavía
no se puede comprar desde la página (eso es la HU-028), por lo que se insertaron
ventas de prueba por SQL.

Qué cuenta como venta: solo los pedidos en estado pagado, preparando, enviado o
entregado. Los pedidos en carrito, confirmados o cancelados NO cuentan.

Cómo se insertan:
  1. configuracion_bebida: una configuración base (sin personalizar) para Menta,
     Limón y Pepino. Es necesaria porque en esta base cada línea de un pedido apunta
     a una "configuración de bebida" (el producto con sus posibles
     personalizaciones), no directo al producto.
       - id_cliente = NULL y es_plantilla_global = TRUE: no es de ningún cliente.
       - precio_final = precio_base: sin recargos.
  2. Variables @cfg_menta, @cfg_limon y @cfg_pepino: guardan el id de cada
     configuración para usarlo en los pedidos sin escribir números a mano.
  3. pedido + detalle_pedido: 3 pedidos del cliente de prueba Benjamin, todos con la
     observación "Pedido de prueba HU-008":

       Pedido      Estado      Productos           Total     ¿Cuenta?
       1           entregado   4 Menta + 2 Limón   $8.940    Sí
       2           pagado      2 Menta             $2.980    Sí
       3           cancelado   10 Pepino           $14.900   NO

     LAST_INSERT_ID() entrega el id del pedido recién creado, para agregarle sus
     líneas. El subtotal de cada línea lo calcula MySQL solo (es una columna
     generada).

Resultado:
  Menta  = 6 unidades -> "Más vendido"
  Limón  = 2 unidades
  Pepino = 0 unidades (su pedido está cancelado)
El pedido cancelado demuestra que solo se cuentan ventas reales: si contara, Pepino
sería el más vendido.

Cuando existan compras reales (HU-028), conviene borrar estos datos de prueba para
que no alteren los reportes de ventas. Se encuentran con:
  SELECT * FROM pedido WHERE observacion LIKE 'Pedido de prueba HU-008%';


6. Producto antiguo AQ-001
--------------------------
Al final de los datos de prueba se desactiva el producto de ejemplo
"Aquaroma Clasica 500ml" (AQ-001):
  UPDATE producto SET activo = FALSE WHERE sku = 'AQ-001';
No aparece en el catálogo ni en el inicio, y su ficha muestra "No encontrado". No se
borra porque tiene un pedido, una receta (formulación) y una orden de producción
asociados. Esto ya estaba así antes; solo se le agregó un comentario explicativo.


7. Administración: stock mínimo, mensajes de contacto y datos de prueba (22 oct 2026)
-------------------------------------------------------------------------------------
Para HU-035, HU-038, HU-039 y HU-040. Hay que volver a ejecutar aquaroma.sql.
Detalle de los cambios en el sitio: docs/CAMBIOS.txt, punto 17.

  Tabla              Cambio                                              Historia
  inventario         +1 columna: stock_minimo DECIMAL(12,3), 5 por       HU-039
                     defecto (umbral de alerta por producto y sucursal)
  mensaje_contacto   TABLA NUEVA: nombre, correo, asunto, mensaje,       HU-035 / HU-012
                     leido y creado_en
  pedido             +1 fila: pedido de prueba CONFIRMADO (3 Limón)      HU-040
  detalle_pedido     +1 fila (la línea de ese pedido)                    HU-040
  inventario         +3 filas: stock en Providencia (Limón 10, Menta 8,  HU-038
                     Mango 3) y mínimo 10 para Durazno en Santiago
  mensaje_contacto   +3 filas de prueba (2 sin leer)                     HU-035

  - inventario.stock_minimo: un producto activo está en alerta cuando en alguna sucursal
    tiene cantidad <= stock_minimo. Con los datos de prueba quedan 4 en alerta: Frutilla y
    Arándano (0 en Santiago), Durazno (8 de 10) y Mango (3 de 5 en Providencia).
  - mensaje_contacto: la usa el panel para mostrar los mensajes sin leer. El formulario de
    HU-012 debe guardar ahí cada mensaje (leido = FALSE).
  - El pedido de prueba HU-040 está en 'confirmado', que no cuenta como venta: no cambia
    "Más vendido". Se encuentra con observacion = 'Pedido de prueba HU-040'.
  - Ajustes de stock desde /admin/stock: se guardan en movimiento_inventario con
    tipo_origen = 'ajuste_manual', tipo 'ajuste' si suman y 'merma' si restan (la columna
    cantidad no tiene signo), y en observacion el motivo con el antes y el después.
  - Al marcar un pedido "Enviado" se crea o actualiza su fila en envio (transportista,
    tracking, fecha_envio y estado 'en_camino'). Si no existía, se copia la dirección
    principal del cliente (cliente_direccion).
